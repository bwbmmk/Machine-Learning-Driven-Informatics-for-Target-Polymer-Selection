# P08 用一条终端命令运行你的程序

以前你可能要改代码里的文件地址。现在让使用者直接在终端里指定读哪个文件、把结果放哪里。

先完成：P07。本关主要练：argparse、命令行参数、成功和失败的返回数字。

第一次做题，先读 [怎么开始](../../START_HERE.md)。下面所有命令都在有 `check.py` 的 `python_handson_pack/` 目录运行。

## 要做成什么样

完成后可以运行：

```powershell
py -m lessons.p08_cli.task --input data/teaching_records.json --output-dir output/run01
```

`--input` 后面是输入文件；`--output-dir` 后面是输出目录。
末尾加 `--preview` 表示“只看处理后的数量，不保存文件”。即使预览，也仍需填写前两个参数。

## 打开哪里，按什么顺序写

先打开 `lessons/p08_cli/task.py`。下面每一步都可以单独当作一次小练习；不要求一次写完整关。

1. **先只解析命令**：在 build_parser 中定义三个参数。先尝试 --help 能列出参数说明。
2. **连接正常处理**：在 main 中拿到参数，再调用 P07 的流程。把返回的汇总用 json 输出。
3. **再做预览**：用户带 --preview 时，只读取、检查、清洗、统计，不调用保存函数，也不创建输出目录。
4. **最后处理预期错误**：文件找不到、JSON 格式错误等情况给出错误消息并返回 2；成功返回 0。不要把自己的未实现错误也遮住。

## 先检查一小步

先做普通模式，再做预览模式。第二次写同一个输出目录时会拒绝覆盖，可以把 run01 改为 run02。

都写完后，再运行整关检查：

```powershell
py check.py P08
```

如果电脑使用 `python`，把命令里的 `py` 换成 `python`。这条命令会运行一组检查；只完成一小步时，其他检查失败是正常的。先看报错最后几行，只解决当前这个问题。

普通关卡不要改 `test_task.py`；它是已经准备好的检查程序。P06 的 `test_student.py` 则明确留给你填写。只定义函数后直接运行 task.py 可能没有输出，这不等于写错；使用本关检查命令或自己写调用。

## 遇到这些词怎么理解

“终端”是输入命令的窗口；“参数”是命令后带的选项；stdout 是正常输出通道，stderr 是错误输出通道；CLI 就是这种用命令操作的程序。

## 写完后核对的具体规则

这部分保留准确的函数名、返回格式和特殊情况，方便检查，也方便其他 AI 辅导。第一次不用全背下来；写到哪个函数，再对照哪条。

build_parser() -> ArgumentParser。main(argv=None) -> 0 成功或 2 预期错误。预期文件/JSON/根对象/输出已存在错误：stderr 非空且返回2；不要把 NotImplementedError 等编程缺陷吞掉。
成功时 stdout 是一个合法 JSON 摘要（允许缩进），不混其他文字。--help 使用 argparse 默认行为即可。
包根目录运行：py -m lessons.p08_cli.task --input data/teaching_records.json --output-dir output/run01
同一命令追加 --preview 时，output/run01 不应被创建或修改；仍需验证输入根对象。输出不能覆盖输入，沿用 P05 的拒绝覆盖规则。

## 完成以后再做

**基本完成**：函数按上述规则通过自动检查；需要展示或文件输出的部分，你也亲自看过结果。自动检查通过不代表后面的加练已经完成。

**再试着解释**：手动连续执行同一输出命令，确认第二次拒绝覆盖；读懂错误提示后换新输出目录。

**加练，主任务完成后再做**：添加 --limit-preview 参数，仅限制屏幕展示行数，不改变实际清洗结果；自己决定新的展示接口并记录。

加练写在 `variations.py`，自己补一个能核对结果的例子；原来的自动检查不一定检查加练。最后在 `NOTES.md` 写三句话：我写了什么、实际运行结果、哪里还不懂。

卡住时可以这样问 AI：“我在 P08 的第 __ 步，请先用日常语言解释这一步，再给一个不同输入的小例子。不要一次给我整关答案。”
