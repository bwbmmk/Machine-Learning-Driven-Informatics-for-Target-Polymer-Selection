# 以写程序为主的学习路线

你已了解 Python 简单用法，因此从“读文件并处理记录”开始。某个知识点不会时，再针对眼前问题补 15–30 分钟；不用先完成一整套课程。当前执行 P01–P12，原来的 T01–T24 不再作为必做路线。

## 1 每一阶段具体练什么

| 任务 | 写出的功能 | 随用随学的 Python 知识 | 综合能力 |
|---|---|---|---|
| P01 | 读取 JSON、输出部分记录 | json、pathlib、list/dict、返回值 | 看清输入输出 |
| P02 | 按 ID 或名称查找 | 循环、条件、函数、空结果 | 分解需求、考虑重复 ID |
| P03 | 温度单位转换 | 参数、float、异常、边界 | 区分格式正确和数值合理 |
| P04 | 批量校验并给出原因 | 函数组合、错误列表、enumerate | 可解释地处理脏数据 |
| P05 | 清洗、去重、导出 CSV/JSON | csv、json、set/dict、复制数据 | 保留原始数据、解释取舍 |
| P06 | 找错与回归检查 | traceback、assert、断点、最小复现 | 用证据定位问题 |
| P07 | 拆成少量模块 | import、职责划分、main | 阅读和维护自己的代码 |
| P08 | 命令行选择输入输出 | argparse、路径、退出状态 | 让工具能被别人使用 |
| P09 | 筛选、排序、统计 | sorted、key、统计、空列表 | 明确计算口径与效率 |
| P10 | 用 Pandas 实现相同结果 | DataFrame、筛选、类型、导出 | 比较两种实现、核对一致性 |
| P11 | 保存图表及分析文字 | Matplotlib、标签、图文件 | 用图解释数据且不夸大 |
| P12 | 独立改需求并整理说明 | 复用、调试、README、Git | 自主实现和清晰表达 |

不要为了“工程化”一开始就建很多目录、设计类继承、上数据库或 Docker。先写一个能读懂的脚本；逻辑开始重复时再抽函数，职责混杂时再拆模块。面向对象可以以后遇到需要长期管理状态的对象时再学。

## 2 八周参考安排

| 周 | 编程重点 | 当周可见成果 |
|---|---|---|
| 1 | P01–P02 | 能读取文件、查询记录 |
| 2 | P03–P04 | 能转换单位、逐行解释错误 |
| 3 | P05 | 一个不会覆盖原始数据的清洗导出脚本 |
| 4 | P06–P07 | 能定位一个错误，把脚本拆成少量函数和模块 |
| 5 | P08–P09 | 带参数的统计筛选工具 |
| 6 | P10 | 与标准库结果一致的 Pandas 版本 |
| 7 | P11 | 两张带正确标签的图和一段结果说明 |
| 8 | P12 | 独立加一项功能，写出别人能照着运行的 README |

每周建议两次 60–90 分钟编程，加一次 45–60 分钟调试和复盘，有余力再加一次练习。若一张卡需要两周就顺延。若 P01–P04 已很熟，直接完成自测后进入 P05，不必按周数等待。

## 3 一次 60 分钟练习怎么安排

1. 5 分钟：写清输入、输出和这次只实现哪一个功能。
2. 10 分钟：先用纸或注释写处理顺序，必要时查一个知识点。
3. 30 分钟：自己编写和运行，优先实现最小版本。
4. 10 分钟：换输入、检查边界，修一个具体问题。
5. 5 分钟：写三行记录——完成了什么、卡在哪里、下次做什么。

这是参考配比；总体约 70% 时间用于写、运行和调试，20% 查资料，10% 总结。不要把时间全部用在整理笔记或让 AI 讲概念上。

## 4 已经会语法，下一步该提升什么

**第一层：把小功能写成函数。** 参数和返回值清晰，计算函数尽量不同时打印、读文件和修改全局变量。P03 的单位转换是典型练习。

**第二层：考虑正常情况之外的输入。** 空文件、字段缺失、重复 ID、非法数字和未知单位都需要明确行为。你不需要让程序永不报错，而是知道哪些错误应反馈给用户，哪些属于代码缺陷应保留 traceback。

**第三层：让同一个程序适应变化。** 换文件路径、换筛选阈值、换输出目录时，不到处修改硬编码；先用函数参数，之后用命令行参数。

**第四层：能够验证自己。** 用几个手算输入核对转换和统计；比较重构前后结果；解释一条数据为什么保留或排除。检查应保护关键行为，不追求测试覆盖率数字。

## 5 综合素养落在实际动作上

| 能力 | 本次如何练 |
|---|---|
| 需求分析 | 开始写代码前，用三句话说明输入、处理和输出 |
| 信息检索 | 优先查函数的官方说明，记录能解决当前问题的一个例子 |
| 调试 | 保存完整报错，缩减到最小输入，再验证修复 |
| 数据意识 | 保留来源和原文件，不把未知、缺失和 0 混为一谈 |
| 工程习惯 | 使用稳定路径；重构前保存版本；写一个准确运行命令 |
| 表达能力 | 每题给函数写简短说明，用自己的话解释一个选择 |
| 安全意识 | 文件内容当数据读取，不用 eval 解析；不要随手覆盖输入 |
| 独立判断 | AI 说“已修复”后亲自运行；遇到不理解的修改先弄清楚 |

Git 是辅助工具：会查看 diff、保存一次 commit 就够用；没有 Git 时可先做版本副本。当前无需上传 GitHub 或维护复杂分支。

## 6 后期只选一个方向扩展

完成 P08 或 P12 后，再选择一个感兴趣的方向：

- 数据与工程：换真实公开数据、增加自动化检查、配置和日志。
- 化学信息学：安装 RDKit，验证 SMILES 并计算几个描述符。
- 机器学习：在经核查的真实标签数据上比较均值基线和一个随机森林。
- 信息安全：把同样的读取、校验、统计方法迁移到自己生成的日志，练失败事件统计和文件完整性记录。

具体入口在任务卡 E01–E04。现在不用提前安装这些扩展依赖，也不用因为还不会机器学习而推迟写第一个程序。
